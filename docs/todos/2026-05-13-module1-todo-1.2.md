# TODO 1.2 Notes

This document collects the `TODO 1.2` notes that were removed from code while refactoring modules 1-4.

## Completed in this refactor

- `Pi3X` now constructs `hand_mano_layer` internally instead of accepting external injection.
- `Pi3X` now constructs `hand_mano_head` eagerly during initialization.
- Lazy `hand_mano_head` creation was removed from `load_state_dict()`, `prepare_model()`, and `forward()`.
- `ho_decoder` bootstrap now happens after base checkpoint loading, so it can copy weights from the already-loaded `decoder` when the base checkpoint does not provide `ho_decoder.*`.
- MANO parameter freezing now lives in `apply_pi3x_training_policy()`.
- `Pi3X` now owns `hand_encoder` construction and hand-query preparation.
- `Pi3X.forward()` now accepts raw hand inputs (`hand_masks`, `hand_owner_index`, `hand_is_right`) instead of external `hand_queries`.
- `Pi3XTrainer` no longer constructs or runs a trainer-owned hand encoder.

## Follow-up notes still outside module 1 scope

- Review hand/object output packaging and naming consistency in `Pi3X.forward()`.
- Collapse object-token handling to the single-object assumption.
- Move hand/object batch formatting and GT construction out of `Pi3XTrainer` and into dataset-side processing.
## Completed in module 3

- `BaseDataset.__getitem__()` now supports dataset-side sample finalization, so datasets can return structured sample dicts instead of only raw `views`.
- `unified_collate_fn()` now collates those structured sample dicts recursively, including nested `views` lists.
- `DexYCBDataset` now materializes three batch-level blocks per sample:
  - `scene_inputs`
  - `gt_metric`
  - `gt_scale_meta`
- `scene_inputs.object_multiview` is now limited to shared multiview reference data only.
- Per-view object fields are now split into `view["object"]` and expanded into `scene_inputs.object_masks` / `scene_inputs.object_valid`.
- `Pi3X.forward()` now accepts `object_masks` and `object_valid` directly, instead of requiring those per-view fields to stay mixed into `object_multiview`.
- `Pi3XTrainer.forward_batch()` now has a precomputed-batch path that consumes dataset-produced `scene_inputs`, `gt_metric`, and `gt_scale_meta`, then only applies the pred-dependent `scene_scale` conversion.
- `DexYCBDataset` now reuses cached/subsampled object template vertices when building per-view 2D object supervision instead of reloading the OBJ each frame.
- `Pi3XTrainer` no longer keeps the legacy `list[view]` fallback path; training now requires the dataset-side precomputed schema.

## Deferred after modules 1-3

- Review whether object 2D supervision should remain, or whether the object branch should regress only pose/scale.
- Replace the trainer-side `vis_export.build_scene_gt_metric(...)` dependency in GT scaling with a lighter scene-only conversion helper.
- Review hand/object output packaging and naming consistency in `Pi3X.forward()`.
- Collapse object-token handling to the single-object assumption.

## Completed in module 4

- `Pi3X.forward()` no longer falls back to legacy `object_multiview["grasped_object_*"]` fields.
- The object branch now requires `object_masks`, `object_valid`, and a shared-only `object_multiview` payload explicitly.
- The object prediction head now enforces the single-object-token assumption and emits `(B, N, ...)` outputs directly instead of reshaping through a generic `num_object_tokens` path.

## Completed in module 5

- `hand_beta_loss` was removed from `HandObjectLoss`.
- `hand_vertices_loss` was removed from `HandObjectLoss`.
- `object_2d_loss` was removed from `HandObjectLoss`.
- `hand_2d_loss` remains implemented, but its configured weight is now zero.
- `Pi3XTrainer.forward_batch()` no longer adds `hand_vertices`, `hand_global_orient_rotmat`, `hand_pose_rotmat`, `object_vertices_2d`, or `object_vertices_2d_valid` to `gt`.
- The hand/object training contract now relies on joints, pose, translation, and scale supervision only.

## Completed in module 6

- `Pi3XTrainer` no longer keeps the legacy hand GT mesh/rotmat helper functions.
- `debug/test_pi3x_trainer_smoke.py` no longer monkeypatches deleted trainer helpers.
- `debug/test_tensorboard_log_cleanup.py` now reflects the current scalar logging contract and no longer expects `object_2d_loss`.
- `debug/inspect_loss_components.py` no longer prints object 2D loss details.
- `debug/export-dexycb-batch-rrd.py` now reads object masks from `view["object"]["mask"]`.
- `debug/inspect_pi3x_2d_projection_consistency.py` now reads object validity, pose, and 2D points from `view["object"]` instead of legacy `object_multiview` fields.
- `DexYCBDataset` now returns `views` / `scene_inputs` / `gt_metric` / `gt_scale_meta` as a structured sample dict, and the dataset contract test now asserts that schema directly.
- `DexYCBDataset` no longer exposes legacy `object_multiview["grasped_object_*"]` fields in the shared multiview payload.
- `pi3/visualization/pi3x_rerun_export.py` now reconstructs GT hand meshes from `hand_pose_mano` / `hand_mano_betas` / `hand_transl` and consumes `view["object"]` for object metadata.
- `debug/test_pi3x_rerun_export.py` now exercises the new rerun contract instead of encoding legacy hand/object GT fields.
- `debug/test_pi3x_dexycb_object_integration.py` now passes `object_masks` and `object_valid` explicitly into `Pi3X.forward()`.
